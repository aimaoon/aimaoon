# Claude Code 実行用プロンプト：動くLINE絵文字40個の企画・制作・検査

Codex版（2026-09-01）を、Claude Code 環境で最後まで実際に動くように書き直した版です。
判定基準・成果物・品質要求は元版を維持し、次の点を実行可能な形へ確定させています。

- Claude Code には「組み込み画像生成ツール」が存在しない前提で、原画の調達方法を先に確定させる分岐を追加
- 検査スクリプトを「後で作る」ではなく、入出力・判定式・終了コード・自己テストまで仕様化
- ネットワーク遮断環境（公式ガイドラインへ到達できない）で止まらないための分岐と、その場合の報告義務を追加
- 元版に残っていた矛盾（提出ZIPの `tab.png` / `main.png`、安全域と画面外退出、容量目標と上限）の優先順位を明文化
- 検査結果を手書きで作文することの明示的禁止（Claude が最も起こしやすい失敗のため）

---

## 0. 実行ルール（最優先。他節と矛盾したらこの節が勝つ）

### 0-1. 捏造の禁止

- `reports/` 以下のCSV・JSON・Markdownは、**すべて実行したスクリプトの出力**として生成する。人力で数値を書き込まない。
- 検査を実行していない項目に `PASS` と書かない。実行できなかった場合の値は `NOT_RUN`、判断保留は `REVIEW` とする。
- 「たぶん問題ない」「一般に十分」といった推定で合格判定をしない。合格判定は必ず数値と閾値の比較で行う。
- スクリプトが未整備であることを理由に、ブレ検査・見切れ検査・透過検査・容量検査・ZIP再検査を省略しない。
- 生成物が存在しない段階で「完成しました」と報告しない。最終報告の各項目は、実ファイルのパスとバイト数を伴う。

### 0-2. 目視検査は必ず実際に画像を開いて行う

Claude は画像を読める。次の場面では、**Read ツールで画像ファイルを実際に開いて確認する**こと。ファイル名やログだけで判断しない。

- 2×2ポーズシートの生成直後（キャラクター崩れ・サイズ差・見切れ・不要物の確認）
- P1〜P6ポーズストリップの承認ゲート
- 第1フレーム40枚の一覧（180px版・32px版の両方）
- 第1フレームと最大動作フレームの並置比較
- 自動検査が `REVIEW` / `FAIL` を返したフレームペア

トークン節約のため、確認画像は**1枚のコンタクトシートへ合成してから読む**。180px版と32px相当版は同一シートの上下段へ並べる。

### 0-3. 停止して確認すべき場面（勝手に進めない）

1. 原画を生成・調達する手段が確定していない（0-5）
2. 基準キャラクターがユーザー未承認
3. 公式仕様が確認できず、既定値で進めてよいかの合意がない（第2節）
4. 提出ZIPに `main.png` と `tab.png` のどちらが必要か確定していない（第2節・第10節）
5. デザイン採点が不合格で、方向性の選択が必要（第6-C節）

上記以外の細かい判断は自分で行い、作業を止めない。

### 0-4. 環境プリフライト（最初のツール実行）

制作を始める前に、次を1回のコマンドでまとめて確認し、結果を `reports/environment.md` へ保存する。

```bash
mkdir -p reports scripts OUTPUT/final previews poses masks
{
  echo "# environment snapshot"; date -u +"checked_at_utc: %Y-%m-%dT%H:%M:%SZ"
  python3 -c "import sys,platform;print('python:',sys.version.split()[0],platform.machine())"
  python3 -c "import PIL;print('pillow:',PIL.__version__)" 2>&1 | head -1
  python3 -c "import numpy;print('numpy:',numpy.__version__)" 2>&1 | head -1
  for c in apngasm oxipng pngquant zopflipng ffmpeg zip unzip; do
    printf '%s: ' "$c"; command -v "$c" || echo "NOT_FOUND"
  done
} | tee reports/environment.md
```

- `Pillow` が無い場合は `pip install --quiet pillow numpy` を試す。失敗したら、その事実を `reports/environment.md` に記録し、ユーザーへ報告して停止する（画像処理なしでは本作業は完了できない）。
- `apngasm` / `oxipng` は任意。無い場合は Pillow のAPNG書き出し＋自前の差分最適化で代替し、代替した事実を `reports/compression-audit.csv` の `optimization_pass` へ記録する。
- ネットワーク到達性も確認する。遮断されている場合は第2節の分岐へ進む。

### 0-5. 原画の調達モードを最初に確定する（Claude版で最重要）

**Claude Code には画像生成ツールが標準で存在しない。** 元版の「組み込み画像生成を使用します」は、そのままでは実行できない。
制作開始前に、次のどれで原画を用意するかをユーザーと確定し、`reports/asset-pipeline.md` へ記録する。

| モード | 内容 | 使える条件 |
|---|---|---|
| A：ユーザー提供原画 | ユーザーが基準キャラクター1枚と、各絵文字の専用ポーズ原画（01〜32は各6枚）を提供。Claudeはマスク抽出・部位分離・リグ・中割り・APNG化・検査を担当 | 常に可能。既定モード |
| B：画像生成API | ユーザーが画像生成APIのエンドポイントとキーを提供し、Claudeが `scripts/gen_pose.py` から呼び出す | ユーザーがキーと利用許諾を提示し、egressが通る場合のみ |
| C：ベクター原画 | ユーザーが承認したSVG原画をパラメトリックに部位変形して原画を作る | ユーザーがSVG原画を提供・承認した場合のみ |
| D：画像生成機能を持つ別環境 | ユーザーが別環境で原画を作り、このセッションへ配置。Claudeは設計・検査・アセンブリ・提出物作成を担当 | 常に可能 |

**禁止：** モード未確定のまま、コードで円・楕円・多角形を組み合わせてキャラクターを描き起こし、それを「原画」として制作を進めること。
モードCはユーザーが承認したSVGに限る。承認のないコード描画キャラクターは、第6節の同一性基準を満たさないため成果物にできない。

原画が1枚も無い状態でこのプロンプトを受け取った場合の正しい初動は、**第1節のヒアリングとデザイン提案（テキスト）＋調達モードの確認**であり、画像生成の代替を自作することではない。

### 0-6. 作業の分割と再開

- 40個を一度に処理しない。`01-04`（プロトタイプ）→ 以降 4個ずつのバッチで進める。記号 `33-40` は独立バッチ。
- バッチ完了ごとに `reports/progress.json` を更新し、成果物を git へコミットする。
- 長時間コマンド（全40個のAPNG書き出し・全検査）はバックグラウンド実行し、完了後に結果ファイルを読む。
- 会話が要約された場合でも、`reports/progress.json` と実ファイルのハッシュから状態を復元して続行する。推測で「完了済み」と判断しない。

## 1. 最初の応答

キャラクターや絵柄が未確定なら、原画調達（0-5）と並行して次を確認・提案する。

- キャラクターまたはモチーフ / 想定購入者と利用場面 / 絵柄・輪郭線・配色・表情の強さ
- 文字の有無 / 参考画像の役割 / 基準にする1枚のサイズ感
- 一言で説明できる商品コンセプト
- 造形または素材の特徴（透明感、クレイ、陶器、フェルト、ソフビ、ゼリー、焼き菓子など）
- 商品一覧で他作品と見分けられる特徴

指定が曖昧なら、設計思想と商品コンセプトが異なる3案と、おすすめ1案を提示する。単なる動物違い・色違い・線幅違いを3案と数えない。
各案について、モチーフ、一言コンセプト、造形、素材感、配色、シルエット、視覚的フック、小サイズ視認性、40種類への展開性、想定ユーザー、他商品と同化しにくい理由を説明する。
ユーザーが「おまかせ」「この案で」と答えたら、追加確認で止まらず制作フローへ進む（ただし0-5の調達モードだけは確定させる）。

キャラクター画像がある場合は勝手に変更せず、顔・体型・耳・髪・模様・線・色を固定する。参考画像はデザイン基準／サイズ基準／種類の参考として役割を区別する。第三者画像は絵柄そのものを複製せず、種類や構造だけを参考にする。

指定キャラクターの独自性が弱い場合も、勝手に別デザインへ変更しない。元の魅力と同一性を残したまま、造形・素材感・配色・視覚的フック・専用エフェクトを強化する3案を提示し、ユーザーが承認した案だけを基準キャラクターへ反映する。

## 2. 現行仕様の確認と、確認できない場合の扱い

制作開始時に次を確認する。

- アニメーション絵文字制作ガイド：`https://creator.line.me/ja/guideline/animationemoji/`
- 絵文字審査ガイドライン：`https://creator.line.me/ja/review_guideline/`

確認日、公式URL、画像数、寸法、DPI、容量、フレーム数、再生時間、ループ数、ZIP内ファイル名を `reports/spec-snapshot.md` へ保存する。
**公式仕様と本プロンプトの既定値が異なる場合、優先すべきは公式仕様。** 差分は `reports/spec-snapshot.md` の「差分と適用結果」へ明記する。

### 2-1. ネットワークが遮断されている場合（Claude Code のリモート環境では頻出）

`WebFetch` が `EGRESS_BLOCKED` 等で失敗したら、次のとおり扱う。

1. `reports/spec-snapshot.md` に `spec_verified: false` と、失敗した日時・URL・エラー内容をそのまま記録する。
2. 下記「暫定既定値」で作業を進めてよいが、**検証済みであるかのように書かない。**
3. ユーザーへ「公式ページへ到達できないため暫定値で進める。提出前に公式ページで各値を確認してほしい」と明示的に伝える。
4. 最終報告の「外部確認が必要な項目」へ、暫定値の一覧をそのまま載せる。

暫定既定値（本プロンプトの標準書き出し）：

| 項目 | 暫定値 |
|---|---|
| 画像形式 | APNG（RGBA、透過あり） |
| 寸法 | 180 × 180 px |
| DPI | 72dpi以上 |
| 画像点数 | 40点（`001.png`〜`040.png`、3桁ゼロ埋め、欠番なし） |
| フレーム数 | 20 |
| 総再生時間 | 4,000ms（1周） |
| ループ回数 | 1（`acTL` の `num_plays = 1`。4,000ms×2回以上は総再生4秒を超えるため不可） |
| 1ファイル容量 | ハード上限 300,000 bytes / 制作目標 285,000 bytes |
| ZIP全体 | 20MB以下 |
| ZIP直下 | `001.png`〜`040.png` ＋ タブ／メイン画像（下記2-2） |

### 2-2. タブ画像・メイン画像の未確定事項（元版の矛盾点）

元版は「`tab.png`（96×74px）を入れ、`main.png` は入れない」と書いているが、LINE Creators Market では
**スタンプの提出物が `main.png`＋`tab.png`、絵文字の提出物は `main.png` を要求する**構成が一般的で、絵文字に96×74の `tab.png` を要求する記述は確認できていない。
本プロンプトはこれを**未確定事項として扱い、憶測で片方に決めない。**

- 公式ページへ到達できた場合：スナップショットの記述に従い、`reports/spec-snapshot.md` の `submission_files` へ確定リストを書き、`scripts/validate_submission_zip.py --manifest-mode {emoji_main|emoji_tab|custom}` で検査する。
- 到達できない場合：ユーザーに「提出ZIP直下の構成（`main.png` の要否とサイズ／`tab.png` の要否とサイズ）」を確認する。回答が得られるまで `LINE_READY.zip` を完成扱いにしない。
- どちらの構成でも、`001.png`〜`040.png` の40点と、`__MACOSX`・`.DS_Store`・フォルダ階層・作業ファイルを含めないことは共通の必須条件。

### 2-3. 審査ガイドラインの自主点検

企画・画像・テキスト・ZIPの各段階で、形式、視認性、文字、重複、モラル、広告、権利、AI利用申告を点検し、`reports/review-guideline-check.md` へ記録する。
既存キャラクター、ロゴ、ブランド、実在人物、作家固有の絵柄を無断使用しない。
**審査通過は保証できない。** 報告では「本制作で実施した検査結果」と「ユーザーが外部で確認すべき項目」を必ず分けて書く。

## 3. 標準40個テンプレートの展開

40個構成は **付録A（標準40個テンプレート）と付録B（アニメーション・バリエーション表）** を唯一の標準とする。外部ファイルを探さない。

- 会話の基本：12個（キャラクター）
- 明るい感情・反応：12個（キャラクター）
- 困った感情：8個（キャラクター）
- 使いやすい文字・記号・エフェクト：8個（キャラクターなし）

標準配分は「キャラクター32個＋記号8個」。40個すべてにキャラクターを出すと一覧が重く単調になるため、33〜40は文章の後ろに付けやすい `OK!`、ハート、汗、`!?`、疑問符、キラキラ、炎、`zzz` とする。
一般的な絵文字一覧は、用途の広さを考える参考にだけ使い、形・配色・配置・質感を複製しない。

テンプレートの意味・第1フレーム・主動作・固有要素を `emoji-plan.json` へ展開する。キャラクターの形に合わない手や動作は、意味と識別性を保ったまま肉球・翼・葉・触手などへ置き換える。

付録Bも必須仕様として展開する。意味と主動作の名称が違うだけでは合格にせず、
`motion_family` / `spatial_path` / `tempo_class` / `beat_pattern` / `peak_hold` / `loop_return_type` の組み合わせを全40個で一意にする。

## 3-B. 必須5条件の同時合格ゲート

各絵文字は次の5条件を**同時に**満たすまで制作済みにしない。1つでも欠けたらAPNG化せず、原画またはキーフレームから作り直す。

1. **第1フレームのサイズ統一**：01〜32はキャラクター本体の幅・高さ・顔幅・中心位置・足元・輪郭線の見かけを基準画像へ揃える。33〜40は記号の光学サイズ・線幅・素材感を揃える。
2. **第1フレームの感情伝達**：第1フレームだけで、文字ラベルなしに感情または会話用途を推測できる。
3. **感情に固有の実動作**：手・頭・上半身・足・尻尾・涙・小物・エフェクトなど、意味を担う部位が実際に位置・角度・形・量を変える。
4. **シリーズ同一性**：01〜32は承認済み基準画像と同じ耳・顔・輪郭・体型・手足・尻尾・線・色を保つ。33〜40は同じ線色・アクセント色・素材感・光源・角の丸みを保つ。
5. **デザイン差別化**：各項目に固有の主役要素があり、類似感情とは構図・表情・ポーズ・身体変形・エフェクト・感情強度のうち最低3軸が異なる。

全体画像を上下左右へ移動・揺らす・回転・傾斜・拡大縮小するだけのアニメーションは、条件3を満たさずすべてNG。
全身バウンドや小さな揺れは補助動作にとどめ、主動作の代用にしない。
記号8個も、単純な点滅・拡大・傾斜ではなく、構成部品が別方向から飛来する／組み上がる／分離する／落下する／交差するなどの実動作を必須とする。

## 4. 第1フレームを先に完成させる

アニメーションを作る前に、キャラクター32個＋記号8個の**第1フレーム40枚をすべて完成**させる。第1フレームは、アニメーションが再生されない画面でも意味が分かる完成状態。

禁止：無表情の通常立ち／動作前の待機・予備動作／意味を決める表情・小物・エフェクトが未出現／キャラクターが小さすぎる・端から一部だけ見える／ファイル名や説明がないと用途が判断できない／記号が未完成で動かないと読めない。

第1フレーム40枚を、180×180pxと実表示相当24〜32pxの両方で一覧化する（`previews/first-frames-180.png`、`previews/first-frames-32.png`）。
一覧はコンタクトシート生成スクリプトで作り、**Read ツールで実際に開いて確認する。**

```bash
python3 scripts/make_contact_sheet.py OUTPUT/first_frames \
  --cols 8 --cell 180 --out previews/first-frames-180.png
python3 scripts/make_contact_sheet.py OUTPUT/first_frames \
  --cols 8 --cell 32 --scale-to 32 --out previews/first-frames-32.png
```

感情判定は、ファイル名・番号・説明文を隠した状態で行う。検査項目：

- 目と眉だけで感情の方向が分かるか
- 口の形が目・眉と矛盾していないか
- 手と体勢が会話用途を補強しているか
- 涙・汗・怒り・疑問・炎・ハート・小物などの意味要素が完成状態で見えるか
- 32px表示でも類似項目と取り違えないか

「動けば分かる」状態は不合格。動く前から分かり、動くことで意味がさらに強くなる構成だけを採用する。

## 5. キャラクターサイズを数値で統一する

「キャンバスが同じ180×180px」だけでは合格にしない。01〜32はユーザー承認済み基準画像1枚から本体の見かけの大きさを測定し、`style-lock.json` へ保存する。
33〜40は各記号の外接矩形・線幅・中心・視覚重量を `symbol_style_lock` として別に保存する。

記録値：`target_character_width_px` / `target_character_height_px` / `target_center_x_px` / `target_baseline_y_px` / `target_face_width_px` / `target_outline_width_px` と各許容差。

標準許容差：

| 項目 | 許容差 |
|---|---|
| 本体の幅・高さ | 基準値の ±5% |
| 中心位置 | ±4px |
| 立ち姿の足元 | ±3px |
| 顔幅 | ±5% |
| 輪郭線 | 見かけ上 ±10% |

- 小物・文字・汗・涙・炎・星・ハートなどのエフェクトを、本体の外接矩形へ含めて測定しない。主役だけのマスク（`masks/NNN-body.png`）で測る。
- 小物が大きい項目でも、主役を縮小して帳尻を合わせない。
- 横向き・寝姿・走行姿勢は全身の縦横比が変わるため、顔幅と線幅を優先して同じサイズに見せる。寝姿だけを無理に縦へ拡大しない。

測定結果を `reports/scale-audit.csv` へ保存する（列：`number,width_px,height_px,center_x_px,baseline_y_px,face_width_px,outline_width_px,width_dev_pct,height_dev_pct,center_dev_px,baseline_dev_px,face_dev_pct,outline_dev_pct,result`）。
許容差を外れた画像は自動補正または再生成し、40枚一覧を再確認する。

**サイズ補正は第1フレームを基準に1回だけ決定する。** 同じ絵文字の第2フレーム以降には、第1フレームで確定した同一の拡大率・基準中心・基準足元を適用する。
各キーフレームを個別に中央揃え・個別正規化してはいけない（お辞儀・ジャンプ・手振り・沈み込みの移動量が消えるため）。
動作によって頭・手・足・エフェクトが基準枠から自然に動くのは許可。キャラクター自体が別サイズへ変化して見える生成崩れは不合格。

## 6. デザイン固定

デザイン確定後、`design-brief.md` と `style-lock.json` を作成する。

`style-lock.json` の記録項目：
`project_name` / `target_audience` / `use_cases` / `character_or_motif` / `one_sentence_product_concept` / `silhouette` / `proportions` /
`face_rules` / `eye_rules` / `mouth_rules` / `line_color` / `line_width_rule` / `base_colors` / `effect_colors` /
`shading_rule` / `highlight_rule` / `shadow_rule` / `gloss_rule` / `depth_rule` / `layer_rule` /
`material_concept` / `texture_rule` / `text_language` / `forbidden_changes` / `copyright_safety_notes` /
`visual_hooks`（大半で維持する記憶点を最低3つ） / `deformable_parts` / `signature_effect_style` /
第5節のサイズ基準 / `symbol_style_lock`（33〜40共通の線色・線幅・角の丸み・素材・ハイライト・影・光学中心・安全域）。

耳・髪・模様・体型・配色・線・顔の配置が変化した画像は採用しない。

承認済みの基準キャラクターを `character-master.png` として保存し、以後これを唯一の同一性基準とする。
**禁止：** コードで似たキャラクターを描き直す／別のAI生成画像を勝手に基準へ差し替える／輪郭を簡略化して別デザインへ変える。

記録するランドマーク：左右の耳先と折れ耳の向き／両目・鼻・口・頬の中心座標と間隔／顔幅と体幅の比率／足の位置と形／尻尾の位置・向き・模様／輪郭線の色と太さ。

第1フレームは承認済み原画そのもの、または同一性検査に合格した派生原画を使う。サイズ調整と透過処理以外の理由で顔や輪郭を再描画しない。

### 6-A. デザイン性と変化の設計

40種類へ展開しても同一性を保ちながら、表情・姿勢・シルエットを変えられる設計にする。
基準デザインには、耳・頭の形・頬・尻尾・模様・質感・専用エフェクトなどから、シリーズを記憶させる視覚的フックを最低3つ設定し、感情やポーズが変わっても大半の絵文字で認識できる状態を維持する。

固定するもの：頭身、顔の基本構造、配色、線、主要な特徴、世界観、視覚的フック、顔パーツの基本配置、シリーズ専用エフェクトのデザイン言語。
変化させるもの：目と口、頭角度、体の向き、手足、構図、感情強度／顔アップ・上半身・全身・座り・寝姿・斜め向き／ふくらむ・つぶれる・しぼむ・丸まる・反る／涙・汗・ハート・キラキラ・怒り線。

各絵文字には主役要素を1つ決め、実表示サイズで最初に目に入る要素を明確にする。
似た意味の2個は表情だけで区別せず、構図・表情・ポーズ・身体変形・エフェクト・感情強度のうち最低3軸を変える。
ただし変形で視覚的フックが失われ、別キャラクターに見えるものは不合格。

### 6-B. 「凝ったデザイン」の定義

細部や装飾を増やすことではない。次から必要なものを選び、造形として一貫させる。

- 独自のシルエット、頭、耳、尻尾、手足、目の形
- 通常の動物配色から一歩進んだ、覚えやすく小サイズでも判別できる配色
- 立体感、柔らかな陰影、ハイライト、光沢、奥行き、レイヤー感
- クレイ、陶器、ミルクガラス、フェルト、刺繍、ぬいぐるみ、ソフビ、グミ、ゼリー、焼き菓子など、一言コンセプトと結び付いた素材感
- 感情による大胆な身体変形とシルエット変化
- キャラクターと融合した、シリーズ専用のハート・涙・汗・怒り・炎・キラキラ

素材表現を無関係に混在させない（陶器コンセプトなら、ハイライト・影・エフェクト・記号にも陶器シリーズの共通言語を持たせる）。

デザイン性として数えないもの：毛を1本ずつ描く／小さな模様や極細線を増やす／細かい服の柄・小物・背景を大量に置く／縮小すると消えるテクスチャ／太線と単色塗りの普通の動物へ表情だけ追加／Unicode絵文字をキャラクターへ置き換えただけの構図。
小サイズで潰れる場合は細部を追加せず、顔・目・手・エフェクト・シルエットを大きくし、線を整理し、コントラストを高める。

### 6-C. デザイン独自性・商品力ゲート

基準キャラクターを固定する前に点検する。

1. デザインの特徴を、動物名や「かわいい」を使わず一文で説明できるか
2. 普通の白猫・柴犬・クマ・ウサギ・ヒヨコ・丸顔・点目と小口だけの量産型に見えないか
3. シルエットだけでも同カテゴリの商品と区別できるか
4. 視覚的フックが装飾ではなく主要造形へ組み込まれているか
5. 40個並べたときに統一感がありながら、もっと見たいと思える変化があるか
6. 小さなサムネイルでも他商品と同化せず魅力が残るか
7. 独自性を高めても、日常会話で使いにくい奇抜さになっていないか

一般的すぎる場合は完成扱いにせず、同一性を残した「造形強化」「素材強化」「専用エフェクト強化」の3方向を提案する。

`reports/design-quality-audit.csv` を作り、各20点・合計100点で採点する（列：`axis,score,max,reason`＋合計行）。
`concept_strength` / `silhouette_originality` / `material_and_depth` / `series_hooks` / `small_size_product_appeal`。
**合計80点未満、またはいずれか1項目が12点未満は不合格。** 採点理由を具体的に記録し、NG項目だけを修正する。

採点とは別に、次の実装ゲートをすべて満たす。

- 32px表示で、目・口・主役要素・シルエットのうち最低2つを即座に認識できる
- 視覚的フック3つのうち最低2つが、01〜32の各第1フレームで確認できる
- 濃い輪郭と塗りのコントラストが、白・黒・淡色の背景上で判別できる（`previews/bg-check.png` に3背景で並べて確認）
- 最大動作を想定しても上下左右8pxの安全域を確保できる構図である
- 端へ寄せること自体が意味ではない絵文字を、見栄えだけのために端へ配置しない
- 小さな装飾を増やさず、主役要素・ポーズ・素材感・光学サイズを優先している

## 7. 重複防止ゲート

原画生成前に `reports/uniqueness-matrix.csv` を作り、全40個について記録する。

列：`number,meaning,conversation_intent,first_frame_silhouette,face_expression,hand_or_body_position,primary_motion,dominant_effect,prop_or_symbol,dominant_visual_element,composition_type,body_deformation,emotion_intensity,distinguishing_feature,similar_candidate_numbers,uniqueness_result`

必須条件：

- 同じ基本シルエットと主動作の組み合わせは1回だけ
- `primary_motion + first_frame_silhouette + dominant_effect` は全件で一意
- 類似候補には、構図・表情・目・口・手・体勢・身体変形・エフェクト・感情強度のうち最低3軸の明確な差がある
- エフェクトだけを変えて別絵文字にしない
- 同じポーズを縮小・反転・色変更しただけの画像を別項目にしない
- 同じ速度曲線・同じ拍数・同じ方向の往復を、対象部位だけ変えて別動作として扱わない
- 総再生時間は全件4,000msに統一するが、最大動作の位置・各フレームの表示時間・拍数・速度曲線は動作ごとに変える
- 第1フレームを入れ替えても意味が成立する2個は重複候補として作り直す

一意性の機械検査は次で行い、結果を `reports/collision-report.md` へ貼る。

```bash
python3 - <<'PY'
import csv, collections
rows=list(csv.DictReader(open("reports/uniqueness-matrix.csv")))
keys=["primary_motion","first_frame_silhouette","dominant_effect"]
c=collections.Counter(tuple(r[k] for k in keys) for r in rows)
dup=[k for k,v in c.items() if v>1]
print("motion-key duplicates:", dup or "NONE")
PY
python3 - <<'PY'
import json, collections
p=json.load(open("emoji-plan.json"))
keys=["motion_family","spatial_path","tempo_class","beat_pattern","peak_hold_ms","loop_return_type"]
c=collections.Counter(tuple(str(i[k]) for k in keys) for i in p["items"])
dup=[k for k,v in c.items() if v>1]
print("variation-key duplicates:", dup or "NONE")
PY
```

生成後は意味・見た目・動きを別々に検査し、`reports/collision-report.md` へ記録する。未解決の重複候補が0になるまでAPNG化しない。

### 7-A. 40個の構図・商品バランス

01〜32のキャラクター構図と33〜40の記号を混在させて見え方を確認する。正面立ち・閉じ目・胸前の手・同じ顔角度が連続しないよう調整する。

| 構図 | 個数 |
|---|---|
| 顔中心または顔アップ | 10〜14 |
| 上半身中心 | 6〜10 |
| 全身と大きなポーズ | 10〜14 |
| 座り・寝姿・後ろ向き・斜め向き | 6〜10 |
| 身体変形またはエフェクトが主役 | 6〜10 |
| 小物を使う演技 | 4〜8 |

8個ごとのまとまりでも、同じ構図が3個以上連続せず、表情・手・シルエット・素材の見せ方が偏らないようにする。
各8個を一覧表示し、「別商品と見分けられるか」「もっと見たい変化があるか」「かわいいだけで終わっていないか」「それでも日常で使いやすいか」を確認する。

## 8. 原画・専用ポーズ

40個を一括で本制作する前に、異なる動作ファミリーから4個を選び、20フレームの販売品質プロトタイプを完成させる。
標準候補：低速全身動作／手前方向のポップ／大ジャンプ／横移動または部品組み立て。
この4個でデザイン同一性・演技量・見切れ・アンカーブレ・300KB圧縮を検証し、失敗方式を修正してから残りへ展開する。

原画の作り方は0-5で確定したモードに従う（Claudeが勝手に描き起こさない）。共通ルール：

- 参考キャラクター（`character-master.png`）を毎回参照する。
- 原則2×2の4ポーズシート単位で用意する。各マスを均等にし、十分なガターを設け、何もマスをまたがせない。
- 全マスでキャラクター本体を同じ見かけの大きさ・基準位置にする。
- 文字・ラベル・透かし・不要な影を入れない。
- 均一なクロマキー背景または真正な透過背景を使い、透過後に緑縁・白縁を検査する。
- 生成した各シートは **Read ツールで開いて確認**し、キャラクター崩れ・耳や模様の変化・サイズ差・切れ・不要物があるマスは作り直す。

### 8-1. 専用ポーズ原画の必須枚数

- **01〜32は各絵文字につき最低6枚の承認済み専用ポーズ原画**を必須とする。4枚への省略は禁止。
- 必須6ポーズ：`P1 意味が完成している第1フレーム → P2 予備動作 → P3 動作途中・通過姿勢 → P4 意味が最も強い最大動作 → P5 反動・着地・受け止め → P6 元へ戻るための別ポーズ`。
  P6はP2/P3の単純な逆再生にせず、減速・余韻・着地・持ち直しの形を描き分ける。
- 6枚はファイル数ではなくポーズ自体が異なること。連続する専用原画間で、
  `手足の接続位置` / `関節角度` / `頭と胴体の相対位置` / `足の接地状態` / `顔パーツ` / `小物との接触・隠れ` / `外形シルエット`
  のうち、動作に関係する最低3項目を変える。全体の平行移動・回転・拡大縮小だけの画像は別ポーズと数えない。
- 記号33〜40も、完成記号の変形だけで済ませず、最低5状態（部品出現／接近／衝突または結合／完成／反動または分散）を作る。

保存先：`poses/NNN/P1-first.png` 〜 `P6-return.png`。
`reports/pose-manifest.csv`（列：`number,pose_id,role,changed_joints,changed_contact,silhouette_change,generated_from_single_warp,identity_result,approval`）へ記録する。
**01〜32の `dedicated_pose_count` が6未満、または `generated_from_single_warp=true` が1件でもあればアニメーション工程へ進まない。**

第1フレームと最大動作フレームの間で、`moving_parts` に指定した部位の位置・角度・形・量が明確に変わらなければ作り直す。

### 8-2. レイヤー分離とリグ

- 最終アニメーションは、承認済み基準キャラクターと、同一性検査を通過した専用ポーズ原画から作る。単一原画のメッシュ変形だけで40個を作らない。
- 最低限 `body` / `head` / `left_arm` / `right_arm` / `legs_or_feet` / `tail` / `face_parts` / `prop` / `effect` を必要に応じて分離する。
- レイヤーは承認済み原画からマスクで抽出する。**コードで近似的な猫・人物・モチーフを描き直してレイヤーを作らない。**
- 動かした部位の背後に隠れていた部分が必要な場合は、元原画の色・線・形を維持した補完用アンダーペイントを1回だけ作り、全フレームで同じものを再利用する。
- `fixed_parts` は絵文字ごとに定義し、その動作で本当に動かない部位だけに限定する。固定対象レイヤーは同一画像・同一座標を再利用する。
  お辞儀・ジャンプ・のけぞり・振り向き・寝転びでは、全身や胴体を一律の固定対象にせず、動作中も安定する接地点または局所ランドマークだけをアンカーにする。
- `moving_parts` だけを `anchor_points` を中心に平行移動・回転・変形・差し替えする。支点をアニメーション中に勝手に移動させない。
- 中間フレームは部位レイヤーの座標・角度・変形量を連続補間するか、専用の中割り原画を使う。**別画像同士の単純なクロスフェードで中間フレームを作らない。**
- 複数キーフレーム画像は、部位の到達位置や形を決める参考として使えるが、固定輪郭が一致しない画像をそのまま最終APNGへ入れない。
- 33〜40はキャラクターを描かず、`symbol_style_lock` を参照して別途作る。8個を色違いにせず、文字の組み立て／箱からの放出／噴出と落下／別方向からの衝突／部品の結合／星の交差／火種からの展開／文字の押し出しと浮遊へ分ける。

### 8-3. 専用ポーズ承認ゲート

中割りの前に、各番号のP1〜P6を横一列へ並べたポーズストリップを180pxと32pxで作り、**Read ツールで開いて**次をすべて満たすまで先へ進まない。

```bash
python3 scripts/make_pose_strip.py poses/001 --out previews/pose-strips/001.png --sizes 180,32
```

- P1・P3・P4・P5のシルエットが32pxでも別ポーズに見える
- P2で本動作と逆方向の予備動作、または力を溜める変化がある
- P3はP1とP4の透明度合成ではなく、手足・関節・接地が描かれた通過姿勢である
- P4は手足・顔・体・小物が意味に合う最大状態で、単なる全体移動や膨張ではない
- P5は作用の結果（ジャンプなら着地、押し出しなら伸び切り後の反動、涙なら拭う動作）を示す
- P6は逆再生コピーではなく、余韻を残しながら第1フレームへ接続できる
- 顔・耳・体形・尻尾・線幅・素材感が6枚すべて同一キャラクターとして一致する
- 全ポーズが安全域内に収まり、最大動作でも見切れない

例：「いいね」は 腕を引く→肩と肘が前へ出る→肉球が手前へ突き出る→腕が反動で戻る。
「やったー」は しゃがむ→足が離れる→空中で手足が開く→膝を曲げて着地。
「応援」は 拳を引く→肩から突き上げる→炎が遅れて立ち上がる→拳と炎が別々に反動する。

## 9. アニメーション

第1フレームを起点に、付録A・付録Bの主動作を実装する。

### 9-1. 時間設計

- 1個につき20フレーム、1周の総再生時間をちょうど4,000ms、ループ1回（`num_plays=1`）。
- 20枚を均等200msにしない。移動途中は短く、感情の決めポーズは長くし、合計を4,000msにする。
- 標準配分：予備動作10〜20% / 本動作25〜40% / 決めの静止10〜20% / 反動と戻り30〜45%。
- 主動作の最大点では1〜2フレーム保持し、小サイズでも読める「間」を作る。
- 20フレームはP1〜P6を通過点として補間する。目安 `P1=F01 / P2=F03-05 / P3=F06-09 / P4=F10-13 / P5=F14-17 / P6=F18-19 / F20=P1へ接続`。動作ごとに最適化してよい。
- 戻り区間を往路の順序反転にしない。接地・重力・慣性・小物の遅れ・表情の余韻を含む別軌道にする。
- フレーム20はループを閉じるためF01と同一でもよい。この場合 **格納20フレーム／固有19フレーム以上**が合格条件。
  フレーム19と20を同一にするなど、連続する同一画像での水増しは禁止。全フレームが同一、または実質的変化がないAPNGはFAIL。

### 9-2. 動きの大きさ

- 手足・頭・小物・記号の主要部品は、原則として最大点まで20〜60px移動させる。小さな表情部品でも12px以上の明確な変化を作る。
- 32px表示で開始・途中・決めが別ポーズに見えなければ動きが小さいためFAIL。
- 例：星を見せる動作は「空の手を背中へ回す→星を取り出す→腕と上半身を大きく動かして頭上または手前へ掲げる」まで実演する。星を回転・点滅・拡大するだけでは不合格。
- 通常項目は全20フレームで上下左右8px以上の安全域を維持する。耳・手・足・尻尾・小物・エフェクトが1フレームでも見切れたらFAIL。
- 滑らかさはフレーム数ではなく、ease-in / ease-out / anticipation / overshoot / settle で作る。

### 9-3. 主動作の実装条件

| 意味 | 実装 |
|---|---|
| お辞儀 | 足元と下半身を固定し、頭と上半身の角度・高さを変える |
| 手振り | 胴体を基準に、片手の角度と先端位置を左右へ変える |
| 拍手 | 胴体を固定し、左右の手の間隔を開閉する |
| 敬礼 | 胴体を固定し、片手を頬横から額へ移動する |
| うなずき | 体の基準位置を保ち、頭の高さと角度を変える |
| ジャンプ | しゃがみ・離床・最高点・着地を作り、足元の接地状態を変える |
| 泣く | 涙の位置・長さ・量と、拭う手の位置を変える |
| 怒る | 拳・眉・怒り記号の形と位置を変え、震えは補助動作にする |
| ハート | 手はハートを抱き、ハート本体の大きさを鼓動させる |
| 走る | 左右の足と手を交互に動かし、横移動と動き線を付ける |
| 仕事 | 手をキーボード上で交互に動かし、画面の光を変える |
| 体調不良 | 頭・上半身をふらつかせ、体温計や汗を追従させる |
| すごい | 片腕を背中へ回し、隠れた星をつかみ、腕・肩・上半身を別ポーズへ変えて星を大きく掲げる |
| OK! | O・K・! が別方向から弧を描いて集まり、衝突して完成する |
| ハート（記号） | 小箱または包みが開き、3つのハートが別々の軌道で飛び出す |
| 汗 | 3粒が異なる始点から噴き出し、それぞれ別の放物線で落下する |
| !? | ! が上から落下し、? が横から飛来して中央で衝突する |
| ？ | 曲線本体と点を別々に動かして組み立て、点だけを大きく跳ねさせる |
| キラキラ | 3つの星が別方向から飛来して中央を交差し、別方向へ広がる |
| 炎 | 火種が跳ね、左右の炎が開き、中央炎が立ち上がる3段階 |
| zzz | 各文字が前の文字を押し出しながら現れ、3本の別軌道で斜め上へ進む |

一覧にない動作も、`moving_parts` と `fixed_parts` を明示してから実装する。

### 9-4. 禁止する偽アニメーション

- 完成画像全体を上下へ動かす／左右へ揺らす／回転する／拡大縮小する／傾けるだけ
- 小さな振動・呼吸・点滅だけで4秒を埋める
- 記号全体を揺らす・拡大縮小する・傾けるだけ
- 小物やエフェクトだけを出現させ、手足・頭・姿勢が第1フレームと同じ
- 同じ画像へエフェクトだけを点滅させ、キャラクターの主動作がない
- 同一画像を表示時間だけ変えてフレーム数を増やす
- 各キーフレームを個別中央揃えして部位の移動を打ち消す
- 別々に描かれた完成画像を順番に並べ、輪郭や顔がフレームごとに変化する
- 別画像同士のクロスフェードで、手や輪郭が二重に見える中間フレームを作る
- 固定するはずの耳・目・輪郭・足元・模様が1px以上不規則に動く
- 元キャラクターをコードの円・楕円・多角形で近似的に描き直す
- 動かしやすさを優先して、耳・顔・足・尻尾・体型を別デザインへ変える
- 単一の完成画像へ局所ワープ・メッシュ変形・膨張・収縮を加えただけで主動作を完成させる
- P1を拡大縮小・回転・傾斜・ワープした画像をP2〜P6として登録し、専用ポーズ数を満たしたことにする
- 手足の接続位置・接地・顔・小物との接触が変わらないまま、外周だけをゼリー状に歪ませる
- 全20フレームを均等速度で往復させ、予備動作・決め・間・反動がない
- 40個すべてを「予備動作→最大動作→逆再生で元へ戻る」の同一構造にする
- 全40個を同じ約1秒周期で同時に膨張・収縮させる

全体のバウンド・反動・揺れ・拡大縮小は、専用の部位動作が成立した後の補助としてのみ許可。

### 9-5. ブレ防止と固定アンカー

- 立ち姿は足元または腰、座り姿は接地面と尻を固定アンカーにする。
- 手の動作では肩または肘を支点にし、胴体レイヤーを動かさない。
- 首振り・うなずきは首を支点にし、下半身と足元を動かさない。
- お辞儀は足元と下半身を固定し、上半身グループを腰または股関節の1点から回転させる。
- ジャンプや走行でも、キャラクター内部の目・耳・模様・線幅は同じリグを維持する。
- 横移動が意味ではない動作（お辞儀・手振り・拍手・いいね等）は、両足中央・腰・胴体中心・顔中心のいずれかを `horizontal_anchor` として固定し、左右へ揺らさない。
- ジャンプは `horizontal_anchor` を固定し縦方向だけを動かす。上端の耳・手・エフェクトが安全枠8pxへ侵入しない。
- 走る・退出・再登場など横移動が意味となる項目だけ `allow_horizontal_travel: true` とし、移動経路を `expected_anchor_path` へ数値指定する。
- ポーズはセル番号ではなく**共通ステージ座標**へ配置し、スプライトシートの列・行境界で座標がリセットされないようにする。
- 可動する手・尻尾・エフェクトを含む外接矩形で毎フレーム中央揃えしない。固定部位のランドマークから横位置を補正する。
- 動作曲線には ease-in / ease-out を使い、フレーム間の座標変化を連続させる。整数座標へ早い段階で丸めず、小数座標で補間する。
- **180pxの4倍（720px）以上で描画し、最終段階で `Image.LANCZOS` により180pxへ縮小する。** 回転する手や輪郭のギザつきを抑える。

判定基準：

- `fixed_parts` のフレーム差分は、指定した固定マスク内の画素差が実質0であること。
- **画像全体の重心や外接矩形中心を左右ブレの判定に使わない**（手・涙・尻尾・エフェクトが正しく動くだけで重心は変わるため）。
- 固定部分の位置ずれは0pxを目標とし、アンチエイリアス差を除く平均変位が0.5pxを超えたらFAIL。
- `allow_horizontal_travel: false` の項目は、`anchor_roi` から追跡した固定アンカーの左右位置レンジを全20フレームで1px以内に保つ。
- アンカー追跡の信頼度が不足する場合は自動PASSにせず `REVIEW` とし、180pxと32pxで目視する。

### 9-6. キャラクター同一性検査

完成後、`character-master.png` と各絵文字の第1フレーム・主要フレームを比較し、`reports/identity-audit.csv` へ記録する。

- 耳の数・左右・折れ方が一致する
- 目・鼻・口・頬の配置比率が許容差内
- 顔幅・体幅・足位置・尻尾位置が許容差内
- 輪郭色と線幅が一致する
- 固定領域の画素が元原画と同一、またはサイズ変換による差だけ
- 可動領域も元原画から抽出した部品、または承認済み差分だけで構成されている

目視で「別の猫・別の人物」と感じる場合は、動きが滑らかでもFAIL。動作のために同一性を犠牲にしない。

### 9-7. 販売品質の演技ゲート

最大動作フレームと第1フレームを横に並べた比較画像を作り、**Read ツールで開いて**次をすべて満たすまで書き出さない。

```bash
python3 scripts/make_peak_compare.py OUTPUT/final/001.png --peak-frame 12 --out previews/peak/001.png
```

- 表情だけでなく、少なくとも1つの手足・頭・体勢・小物が別ポーズになっている
- 2枚のシルエット差を32px表示でも認識できる
- 動作名を隠しても、お辞儀・手振り・拍手・ジャンプ・泣く・走るなどの行為を推測できる
- 単なる上下移動・揺れ・膨張・輪郭のゴム変形に見えない
- 主要部品の移動が原則20px以上で、32px表示でも途中ポーズと決めポーズが別状態に見える
- 180pxの全フレームで通常項目に上下左右8px以上の安全域があり、見切れがない
- 決めポーズの前後に速度差と短い静止があり、機械的な往復に見えない
- 第1フレームへ戻る際に、顔・耳・線が別キャラクターへ切り替わったように見えない
- 6種類以上の専用ポーズがあり、単一原画の変形だけで作られたポーズが0枚である
- 往路と復路が完全対称ではなく、予備動作・作用の結果・反動または着地が読み取れる

### 9-8. APNG書き出しの実装（Pillow）

```python
# scripts/build_apng.py の中核
from PIL import Image
frames = [...]            # 20枚の RGBA / 180x180 / 透明画素は RGB=0 に正規化済み
durations = [...]         # 要素数20・整数ms・合計 4000

assert len(frames) == 20 and len(durations) == 20 and sum(durations) == 4000
frames[0].save(
    out_path, format="PNG", save_all=True, append_images=frames[1:],
    duration=durations,                 # ms（APNGでは delay_num/1000 として書かれる）
    loop=1,                             # acTL num_plays = 1（0は無限ループなので使わない）
    disposal=Image.Disposal.OP_BACKGROUND if hasattr(Image, "Disposal") else 1,
    blend=0,                            # APNG_BLEND_OP_SOURCE：透過を含む差分矩形の差し替え
    default_image=False, optimize=False, dpi=(72, 72),
)
```

**書き出したら必ずラウンドトリップ検証する。** エンコーダの差分最適化・disposal の解釈違いによる崩れは、この検証以外では気付けない。

```python
# 読み戻して、合成後の各フレームが元フレームと画素一致するか確認する
from PIL import Image, ImageSequence
import numpy as np
im = Image.open(out_path)
decoded = [f.convert("RGBA") for f in ImageSequence.Iterator(im)]
assert len(decoded) == 20
for i, (a, b) in enumerate(zip(frames, decoded)):
    d = np.abs(np.asarray(a, np.int16) - np.asarray(b, np.int16))
    assert d.max() <= 1, f"frame {i} roundtrip mismatch: {d.max()}"
```

一致しない場合は `disposal` / `blend` の組み合わせを変えて再検証する。一致するまでその絵文字を完成扱いにしない。
`apngasm` が使える環境では、Pillow出力と `apngasm` 出力の両方を検査し、ラウンドトリップに合格したうえで小さい方を採用する。

透明画素の正規化：

```python
import numpy as np
a = np.array(img)              # RGBA
a[a[..., 3] == 0, :3] = 0
img = Image.fromarray(a)
```

### 9-9. 300KB内で動きを最大化する容量設計

300,000 bytes はハード上限、285,000 bytes は制作目標。285,001〜300,000 は提出可能でも `REVIEW`、300,001以上は `FAIL`。

- 容量のために、主動作の20〜60px振幅・20フレーム・4,000msを先に削らない。減らすのは「毎フレーム変化する画素面積」と「色の複雑さ」。
- `fixed_parts` に指定した部位だけは、全20フレームで位置とRGBA値を一致させる。胴体・顔・接地足を全項目で一律に固定せず、演技上動く部位は `moving_parts` へ移す。固定部位を毎フレーム描き直さない。
- 腕・脚・頭・小物・涙・星などの `moving_parts` は別レイヤーにし、小さな可動領域を20〜60pxの大きな軌道で動かす。全身画像を大きく平行移動するより、意味を担う部位を大きく動かす。
- APNGはフルフレーム20枚の単純格納にせず、前フレームとの差分矩形を最小化して符号化する。9-8のラウンドトリップ検証を必ず通す。
- 透明画素のRGBを0へ正規化し、PNGメタデータを除去し、可逆最適化を行う。
- 太い一定の輪郭、ベタ塗り、少数の共通色、固定された1段影とハイライトを使う。フレームごとに変わる粒状テクスチャ・ノイズ・ディザ・広い半透明グロー・ぼかし影・複雑なグラデーションは禁止。
- RGBA要件を維持したまま、必要時だけ色精度と階調を整理する。輪郭・顔・第1フレーム・商品固有色を優先し、主動作の形や振幅を劣化させない。
- 粒子を減らす場合は、意味を担わない小粒子から減らす。

容量超過時の修正順（途中で主動作を小さくしない）：

1. 透明画素のRGB正規化、メタデータ削除、可逆最適化（`oxipng -o4 --strip safe` など。無ければPillowの再保存）
2. 差分矩形・blend・disposalの最適化
3. 固定領域をバイト単位で同一化し、影・ハイライトの不要なフレーム変化を除去
4. 形を変えずに色階調・半透明階調を整理
5. 意味を担わない粒子・ぼかし・細線・装飾を削減
6. 主動作の振幅を保ったまま、可動レイヤーと更新矩形を再設計
7. それでも300,000 bytesを超える場合は完成扱いにせず、圧縮しやすい原画構造から再生成

`reports/compression-audit.csv`（列：`number,bytes_before,bytes_after,target_met,hard_limit_met,frames,unique_frames,cycle_ms,max_changed_bbox_ratio,fixed_region_byte_identity,optimization_pass,roundtrip_result,visual_quality_result`）へ記録し、
圧縮後も180pxと32pxで輪郭ちらつき・色ムラ・感情の読みやすさ・動作振幅を再確認する。

## 11. 検査スクリプト仕様（この通りに実装する）

`scripts/` に存在しない場合は、以下の入出力・判定式・終了コードを満たすスクリプトを**先に作り、自己テストで動作確認してから**使う。
「スクリプトが無いので目視だけにした」は不可（0-1）。

共通ルール：

- 依存は Python 3 + Pillow + numpy のみ。追加ツールは任意扱いにし、無ければ機能を落として続行し、その旨を出力へ書く。
- 判定は `PASS` / `REVIEW` / `FAIL` / `NOT_RUN` の4値。
- 終了コード：`0`=FAILなし かつ REVIEWなし、`2`=REVIEWのみ、`1`=FAILあり、`3`=実行エラー。
- 標準出力にサマリ（件数と最初の10件の不合格）、詳細はCSV/JSONへ。
- 検査対象は必ず実ファイル。計画JSONの値ではなく、書き出し済みAPNGを読む。

### 11-1. `scripts/check_apng_jitter.py`

```bash
python3 scripts/check_apng_jitter.py <APNG_DIR> --config reports/anchor-config.json \
  --output-dir reports/jitter [--items 001,002] [--fail-on review]
```

- 対象は `<APNG_DIR>` 内の `001.png`〜`040.png` のみ。`tab.png` / `main.png` は除外する。
- `reports/anchor-config.json` のスキーマ：

```jsonc
{
  "defaults": {
    "anchor_search_px": 8,          // アンカー探索半径（通常6〜12）
    "max_anchor_range_px": 1.0,     // 横位置レンジの上限（allow_horizontal_travel=false時）
    "max_mean_fixed_displacement_px": 0.5,
    "safe_area_px": 8,
    "alpha_threshold": 8,           // 見切れ判定に使うアルファ閾値
    "jitter_step_ratio": 4.0,       // 隣接ステップが中央値の何倍で突出とみなすか
    "jitter_step_min_px": 2.0,
    "match_confidence_min": 0.90    // 追跡信頼度。下回れば REVIEW
  },
  "items": {
    "001": {
      "anchor_roi": [78, 138, 24, 20],
      "horizontal_anchor": "feet_center",
      "allow_horizontal_travel": false,
      "allow_stage_exit": false,
      "fixed_mask": "masks/001-fixed.png",     // 任意。白=固定領域
      "expected_anchor_path": null,             // allow_horizontal_travel=true のとき必須
      "safe_area_px": 8
    }
  }
}
```

処理：

1. APNGを **合成後（disposal/blend適用後）のRGBAフレーム列**へ展開する（`ImageSequence.Iterator` の各フレームを `convert("RGBA")`）。フレーム数が20でなければ `FAIL` として続行。
2. フレーム1の `anchor_roi` をテンプレートとし、各フレームで ±`anchor_search_px` を全探索。
   スコアはアルファで重み付けしたRGBの二乗誤差和（SSD）の最小値。最小位置の周囲でX/Yそれぞれ放物線フィットしてサブピクセル座標を得る。
3. 追跡信頼度 = `1 - min_ssd / second_best_ssd`。`match_confidence_min` を下回るフレームがあれば、その番号は `REVIEW`（自動PASSにしない）。
4. `horizontal_anchor_range_px = max(x) - min(x)`。`allow_horizontal_travel=false` で `max_anchor_range_px` 超過 → `FAIL`。
   `true` の場合は `expected_anchor_path` との各フレーム差が 2px を超えたら `FAIL`。
5. `max_adjacent_horizontal_anchor_step_px` を求め、`step > median(step) * jitter_step_ratio` かつ `step > jitter_step_min_px` のペアがあれば `FAIL`（カクつき）。
6. `fixed_mask` があれば、マスク内画素をフレーム1と比較。`fixed_region_difference_ratio = 差分が2/255を超える画素の割合`。
   0.005（0.5%）超過 → `FAIL`。平均変位が `max_mean_fixed_displacement_px` 超過 → `FAIL`。
7. 見切れ：各フレームで `alpha > alpha_threshold` の外接矩形を求め、キャンバス端からの余白が `safe_area_px` 未満 → `FAIL`。
   `allow_stage_exit=true` の項目は見切れ判定から除外するが、退出前後の輪郭崩れは6の固定領域検査で見る。
8. ループ境界：F20→F01 のアンカー移動量が、他の隣接ステップ中央値の `jitter_step_ratio` 倍を超えたら `FAIL`。
9. 出力：
   - `reports/jitter/jitter-audit.csv`
     列：`number,frames,anchor_confidence_min,horizontal_anchor,horizontal_anchor_range_px,max_adjacent_horizontal_anchor_step_px,loop_boundary_step_px,fixed_region_difference_ratio,mean_fixed_displacement_px,min_safe_margin_px,allow_horizontal_travel,allow_stage_exit,result,reasons`
   - `reports/jitter/NNN-transitions.csv`
     列：`from_frame,to_frame,anchor_dx_px,anchor_dy_px,step_px,changed_pixel_ratio,bbox_margin_px,flag`

`REVIEW` / `FAIL` の項目は、遷移CSVが示すフレームペアを180pxと32pxの両方で目視する（0-2）。
毎フレーム全身を描き直したことによる輪郭の脈動は、中間フレームを増やして解決せず、固定パーツを同一画像へ戻して修正する。

### 11-2. `scripts/validate_apng_set.py`

```bash
python3 scripts/validate_apng_set.py <APNG_DIR> --expected-count 40 --strict-standard \
  [--json reports/apng-audit.json] [--frames 20] [--cycle-ms 4000] [--loops 1]
```

検査項目（`--strict-standard` 有効時）：

| 項目 | 合格条件 | 不合格時 |
|---|---|---|
| 連番 | `001.png`〜`040.png` が欠番なし・余分なし | FAIL |
| 寸法 | 180×180 | FAIL |
| 形式 | PNGカラータイプ6（RGBA）／インターレースなし | FAIL |
| APNG構造 | `acTL` が存在し `num_frames=20`、`num_plays=1` | FAIL |
| 総再生時間 | 全 `fcTL` の `delay_num/delay_den` 合計 = 4000ms（誤差0） | FAIL |
| 固有フレーム | 合成後フレームのハッシュ種類が19以上 | FAIL |
| 連続同一 | 隣接する合成後フレームが完全一致するペアが2組以上 | FAIL |
| 容量 | ≤285,000 → PASS / 285,001〜300,000 → REVIEW / >300,000 → FAIL | 左記 |
| 透明画素RGB | `alpha==0` の画素のRGBがすべて0 | REVIEW |
| メタデータ | `tEXt`/`iTXt`/`zTXt`/`eXIf` が無い | REVIEW |
| 安全域 | 全フレームで端からの余白 ≥8px（`allow_stage_exit` を除く） | FAIL |
| ラウンドトリップ | 再デコードしたフレームが `OUTPUT/frames/NNN/` の元フレームと最大差1以内 | 元フレームが無ければ `NOT_RUN` |

`delay_den=0` は 1/100 秒として解釈すること（APNG仕様）。総再生時間の計算はここを間違えやすい。
出力JSONは `{"items":[{"number":"001","checks":{...},"result":"PASS"}],"summary":{...}}`。

# 付録A：動くLINE絵文字・標準40個テンプレート

## 目的

日常会話で使いやすく、一覧表示でも飽きにくい40個を、キャラクターを差し替えて繰り返し制作するための標準構成。
キャラクター32個と、文章の後ろへ付けやすい記号8個で構成する。
「似た意味を表情だけ少し変えて増やす」のではなく、会話用途・第1フレームのシルエット・主動作を分ける。
似た感情同士は、構図・表情・ポーズ・身体変形・エフェクト・感情強度のうち最低3軸を変える。

## 共通制作ルール

- 01〜32は同じ基準キャラクターを表示し、33〜40はキャラクターなしの記号・文字・エフェクトにする。
- 第1フレームだけで意味が伝わる完成ポーズにする。
- 全項目を20フレーム・総再生時間4,000ms・ループ1回で制作する。各フレームの表示時間と決めポーズの位置は動作ごとに変える。
- 01〜32は各項目につき最低6枚の専用ポーズ原画（P1完成／P2予備／P3通過／P4最大／P5反動・着地／P6戻り）を作る。単一原画の伸縮・傾斜・ワープを別ポーズと数えない。
- P1・P3・P4・P5は32px表示でもシルエットが別状態に見え、手足の接続・関節角度・接地・顔・小物との接触のうち、動作に関係する最低3項目が変わること。
- 33〜40も完成記号の変形だけにせず、部品出現／接近／衝突・結合／完成／反動・分散の最低5状態を作る。
- 主動作は32px表示でも開始・途中・決めを別状態として判別できる大きさにする。手足・頭・小物は原則20〜60px動かす。
- 画面全体の揺れ・拡大縮小・傾きだけで完成させることは禁止。必ず手足・頭・胴体・小物・記号の構成要素が別位置／別角度／別形状へ変わる実動作を入れる。
- 全20フレームで上下左右8px以上の安全域を確保し、大きな動きでも耳・手・足・小物・エフェクトを見切れさせない。
- 1ファイル300,000 bytes以下をハード上限、285,000 bytes以下を制作目標にする。容量のために20フレーム・4,000ms・主動作20〜60pxを先に削らない。
- 固定部位は絵文字ごとに定義し、その動作で本当に動かない部位だけ全20フレームでRGBAを一致させる。可動部位は小さな別レイヤーとして大きく動かし、APNGは最小差分矩形で符号化する。
- ベタ塗り・太い一定線・少数の共通色・固定された1段影を使う。粒状ノイズ、ディザ、動くグラデーション、広い半透明グロー、ぼかし影は禁止。
- 容量超過時は、透明画素RGB正規化 → メタデータ削除 → 可逆最適化 → 差分矩形最適化 → 固定画素の同一化 → 色階調整理 → 不要粒子削減の順で直す。主動作の振幅を小さくする修正は最後まで行わない。
- 同じ基本シルエットと主動作の組み合わせは1回だけ。
- 各項目に、最初に目へ入る主役要素を1つ設定する。
- キャラクター固有の視覚的フックを最低3つ決め、全身・顔アップ・変形ポーズでも同一キャラクターと認識できる状態を維持する。
- 33〜40にも、キャラクターと同じ線色・アクセント色・素材感・角の丸み・光と影を適用する。
- 動物名や「かわいい」を使わず説明できる、一文の商品コンセプトを設定する。
- 細部を増やすのではなく、シルエット・素材・立体感・身体変形・演出で商品力を高める。
- 同じ手の位置を使う場合は、体勢・表情・小物のすべてを変える。
- 本体の見かけの大きさ・中心・足元・線の太さを01〜32で統一する。33〜40は記号ごとの光学サイズを揃える。
- 横移動が意味ではない項目は、足元・腰・胴体・顔のいずれかを横方向の固定アンカーにし、全20フレームの左右差を1px以内にする。
- 左右ブレは画像全体の重心ではなく、`anchor_roi`（接地足・腰・尻・胴体中心など）を追跡して判定する。動く手・尻尾・涙・小物・エフェクトをアンカーへ含めない。
- エフェクトや小物を理由にキャラクター本体を小さくしない。
- 記号だけにするのは33〜40の8個に限定する。
- 第1フレームを40個並べ、意味・見た目・動きの重複を生成前後に検査する。
- フレーム20はループを閉じるため第1フレームと同一でもよいが、フレーム19と20を同一にしない。格納20フレーム・固有19フレーム以上を維持する。

## B-1. 分散条件

- 同じ `動作ファミリー + 軌道 + 拍数` の組み合わせを2個以上で使わない。
- 40個を、低速12個前後・中速16個前後・高速12個前後へ分散する。
- 01〜32では強いシルエット変化／手足中心／小物・エフェクト中心／静かな呼吸を混在させ、33〜40では文字・記号・粒・光・炎・浮遊を分散する。
- 連番で同じテンポ・同じ方向・同じ拍数が3個以上続かないよう並びを調整する。
- 単純な等速往復は全40個中4個以下とし、それ以外は静止・加速・遅延・オーバーシュート・退出のいずれかを含める。
- `予備動作 → 最大動作 → 戻る` だけで全件を作らず、二段動作・三連打・順次出現・画面退出・戻らず終了する演技を含める。
- 画面全体の揺れだけ／拡大縮小だけ／傾きだけの項目は0個。
- 単一の完成画像を伸縮・傾斜・ワープしただけの項目は0個。01〜32は専用ポーズ6枚が揃うまで中割りとAPNG化へ進まない。
- 主要部品が20px未満しか移動せず、32px表示で開始と決めを区別できない項目は再設計する。
- 動作範囲は大きくするが、全フレームで安全域を確認し、見切れを1フレームも許可しない。退出そのものが意味の演技だけ `allow_stage_exit` として事前指定する。
