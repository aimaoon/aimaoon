# Stage Note — ダンスコンテスト管理アプリ

出るコンテストごとに、**入金・音源提出・会場・ジャッジ・振り返り**を 1 か所にまとめるスマホ向けアプリです。
「あの大会、入金したっけ？」「音源の締切いつだっけ？」を無くすのが目的です。

ブラウザで動く PWA なので、スマホで開いて「ホーム画面に追加」すると全画面のアプリとして使えます。
データはその端末の localStorage にだけ保存されます。通知サーバーを立てた場合にかぎり、
通知の日時と文言だけがそちらに預けられます（下の「通知サーバー」を参照）。

使う人向けの説明は [`docs/manual.md`](docs/manual.md) にまとめてあります
（画面写真つきの版: https://claude.ai/code/artifact/583958f6-9969-4ddf-b500-7d27f67ce6e0 ）。

## 画面

| タブ | 中身 |
| --- | --- |
| イベント | 締切アラート → 未記入の振り返り → コンテスト一覧（これから / 要対応 / 終わった / すべて）。検索とジャッジ・ファイナル権での絞り込み |
| カレンダー | 開催日・ファイナル・入金期限・音源期限を月表示。日付をタップすると内訳が出る。上の検索窓で予定そのものを横断検索 |
| 通知 | これから鳴るリマインダーを時系列で表示。通知の許可と .ics 書き出し |
| 設定 | 未入金の合計などのサマリー、バックアップの書き出しと復元、配色、.ics 書き出し、アプリの情報 |

コンテストの詳細画面では、大会名や日付といった変わりにくい情報は「編集」画面で、
入金状況・音源の提出状況といった日々変わる状態はその場で切り替えられるようにしています。

## 管理できること

### 入金対応

`未入金 / 一部入金 / 入金済み / 費用なし` の 4 状態。エントリー費・入金期限・入金日・振込先メモを持ちます。
一部入金のときは残額を自動計算します。入金期限を設定すると、期限当日の 9:00 に通知が出て、
カレンダー（.ics）にも終日予定として書き出されます。入金が済めばその通知は自動で消えます。

### 音源提出

提出状況は `未準備 / 用意済み / 提出済み` の 3 段階。これとは**別軸のチェックとして「当日持参」**を
横に置いています。事前提出とは独立しているので、次のどちらも表せます。

- 事前提出のない大会 → 用意済み ＋ 当日持参
- 提出は済ませたうえで、当日 USB も持っていく → 提出済み ＋ 当日持参

**当日持参にチェックが入っていれば、事前提出が未了でも「対応済み」として扱い**、提出期限の通知は出しません。
曲名・提出期限・提出日・提出方法（フォーム / メール / 当日 USB）・尺や編集のメモも残せます。

### 開催場所の地図

会場名・住所・（任意で）緯度経度を入れると、Google マップと経路検索を 1 タップで開けます。
座標があれば座標を、なければ住所を、住所もなければ会場名を検索語にします。
入口や楽屋の場所などは会場メモに書けます。

### ファイナル（決勝）

予選とは別日・別会場になる決勝を、同じ大会の中に別枠で持てます。
詳細画面のカード先頭にある「ファイナル権」の 4 択が唯一の入口です。

| 選択 | データ | 画面 |
| --- | --- | --- |
| ファイナル無し | `final` を持たない（既定） | 日程の欄は出ない |
| 結果待ち | `status: 'undecided'` | 日程・会場・リマインダーを入力できる |
| ファイナル権獲得 | `status: 'advanced'` | 同上。一覧の絞り込み対象になり、カードにトロフィーのバッジが付く |
| 予選敗退 | `status: 'eliminated'` | 通知・カレンダーから外れ、日程の欄は畳む（データは残す） |

以前は「ファイナル権を獲得した」というボタンだったのを、状態を選ぶ形に変えています。
獲得したという断定に見えて押しにくい、という指摘に対する変更です。

- **権利だけ先に決まって日程が未発表**でも記録できます（開催日は空のままで構いません）。
- 日程が入っていれば、**予選が終わってもファイナルが残っている間は「これから」の一覧に残ります**
  （一覧の日付表示も自動でファイナルの日に切り替わります）。
- 会場を空欄にしておくと予選と同じ会場として扱います。
- 「ファイナル無し」に戻すと日程・会場・リマインダーごと消えるので、中身があるときだけ確認を挟みます。
- 日程未定のあいだは通知・カレンダーの対象外なので、一覧では「終わった / すべて」に入ります。
  下記のファイナル権フィルタで拾えます。日程を入れれば自動で「これから」に戻ります。

### ジャッジ

名前とジャンルに加えて、「見られるポイント」「前回の反応」をメモできます。対策を思い出すためのメモ欄です。

### 検索と絞り込み

- **イベントタブの検索窓**は、大会名・部門・会場・ジャッジ名・曲名・当日メモを対象にします。
- **ジャッジで絞り込み**：登録済みのジャッジが担当した大会の多い順に並びます。複数選ぶと
  「選んだ誰かがいる大会」（OR）になります。名前は大文字小文字と前後の空白を無視して突き合わせるので、
  `KENTO` と `kento ` は同じジャッジとして扱われます。
- **ファイナル権獲得で絞り込み**：権利を獲得した大会だけに絞ります。
- 絞り込みは「これから / 要対応 / 終わった / すべて」の切り替えと重ねてかかります。過去の大会も含めて
  見たいときは「すべて」に切り替えてください。
- **カレンダータブの検索窓**は予定そのものを横断検索します。大会名・会場・支払い方法などに加えて、
  「入金」「音源」「ファイナル」といった種別名でも引けます。既定では過ぎた予定を隠し、
  チェックを入れると過去も含めて出します。

### バックアップと復元

データは端末の中にしかないので、機種変更やブラウザのデータ削除で消えます。
設定タブから控えを書き出し、そのファイルから元に戻せます。

- **書き出し** — 日付入りのファイル名（`stage-note-20260820.json`）で保存します
- **読み込み** — 2 通りから選べます
  - **いまの内容に足す** … 同じ大会は更新が新しいほうを残します（別の端末の控えを取り込むとき）
  - **すべて置き換える** … 手元を捨てて控えの内容にします
- 最後に控えを取ってから 2 週間経つと、設定タブで促します
- 以前の形式（コンテストの配列をそのまま書き出したもの）も読み込めます

### 初回の案内

はじめて開いたときは、何のアプリかを説明したうえで
「最初の大会を登録する」か「サンプルで中身を見る」を選んでもらいます。
いきなりサンプルが並んでいると自分のデータに見えないため、空から始められるようにしています。

### 振り返りメモ

5 段階の自己評価・結果・よかったこと・課題・次にやること。
終わったのに振り返りが未記入の大会は、ホームの先頭で促します。

### カレンダーとリマインダー

大会ごとにリマインダーを何本でも設定できます（初期値は 1 週間前 / 前日 / 当日の朝）。
ファイナルには別枠で設定できます。受け取り方は 3 通りあり、上から順に確実です。

1. **プッシュ通知（アプリを閉じていても届く）** — 通知サーバーを立てると使えます。下の「通知サーバー」を参照。
2. **開いている間の通知** — サーバーが未設定のときの代わり。24 時間以内のぶんをブラウザ通知で出します。
3. **.ics の書き出し** — スマホの標準カレンダーに予定とアラームごと取り込みます。
   端末を変えても鳴るので、1 と併用しても構いません。

1 が有効なときは 2 を止めます（同じ通知が二重に鳴らないように）。

## 配信とホーム画面への追加

このアプリはブラウザで動くので、まず自分の URL に置きます。通知サーバーと同じ
Cloudflare に置くと管理先が 1 つで済みます。やり方は 2 通りです。

**A. ブラウザだけで（ターミナル不要）**

GitHub にあるこのリポジトリを Cloudflare につなぐと、以降は push するたびに自動で配信されます。

1. [dash.cloudflare.com](https://dash.cloudflare.com) でサインアップ（無料）
2. 左メニューの **Workers & Pages** → **Create** → **Pages** → **Connect to Git**
3. このリポジトリを選び、**production branch** にこのアプリのブランチを指定する
4. ビルド設定を次のようにして **Save and Deploy**

   | 項目 | 値 |
   | --- | --- |
   | Framework preset | None |
   | Build command | `npm run build` |
   | Build output directory | `dist` |

5. 数分で `https://<プロジェクト名>.pages.dev` が発行される

Node のバージョンは `.node-version`（22）で固定してあるので、そのままビルドが通ります。

**B. 自分の PC から**

```bash
git clone https://github.com/aimaoon/aimaoon.git
cd aimaoon
git checkout claude/dance-event-management-app-ngol30
npm install
npx wrangler login      # ブラウザが開くので許可する
npm run pages:deploy    # ビルドして配信。URL が表示されます
```

どちらでも、表示された URL（例 `https://stage-note.pages.dev`）がこのアプリの住所になります。

**スマホへの入れ方（iPhone）**

1. Safari でその URL を開く
2. 下の共有ボタン → **「ホーム画面に追加」**
3. 追加された Stage Note のアイコンから開く（Safari のタブからではなく）

3 が重要です。iOS はホーム画面のアイコンから起動したときだけ通知を許可します
（Safari のタブのままだと、通知タブのボタンを押しても登録できません）。
Android は Chrome の「アプリをインストール」から同じことができます。

## 通知サーバー

アプリを閉じていても通知を出すには、時刻が来たときに外から push を送る側が必要です
（ブラウザだけで未来の通知を予約する仕組みは、iPhone では使えません）。
`worker/` に Cloudflare Workers 用のものを置いてあります。

**預けるのは通知に必要な最小限だけ**です。通知の日時・タイトル・本文と購読情報のみで、
エントリー費・ジャッジのメモ・振り返りは端末に残ります。予定を変えるとアプリが自動で送り直し、
サーバー側は毎回まるごと置き換えるので、消した予定が残り続けることはありません。

```bash
npm run vapid                       # 1. 鍵を作る（公開鍵と秘密鍵が出ます）
npx wrangler d1 create stage-note   # 2. データベースを作り、出た database_id を worker/wrangler.toml に貼る
npm run worker:schema               # 3. 表を作る
cd worker
npx wrangler secret put VAPID_PUBLIC_KEY    # 4. 秘密を入れる（1 で出た値）
npx wrangler secret put VAPID_PRIVATE_KEY
npx wrangler secret put APP_TOKEN           #    任意。設定すると合言葉を持つ端末だけ登録できます
cd ..
npm run worker:deploy               # 5. デプロイ。表示された URL を控える
```

`worker/wrangler.toml` の `VAPID_SUBJECT` は自分のメールアドレスに変えてください
（送信先の push サービスが連絡先として使います）。`ALLOWED_ORIGIN` にアプリの URL を入れておくと、
そこからのリクエストだけを受け付けます。最後にアプリ側の `.env` を作ります。

```
VITE_PUSH_API=https://stage-note-push.<あなた>.workers.dev
VITE_VAPID_PUBLIC_KEY=<1 で出た公開鍵>
VITE_PUSH_TOKEN=<APP_TOKEN を設定したときだけ>
```

`.env` を作ったら、アプリを配信し直します（`npm run pages:deploy`）。
ビルド時に埋め込む値なので、配信し直さないと反映されません。

これで通知タブに「この端末で受け取る」が出ます。上の手順どおり、
**ホーム画面に追加したアイコンから開いて**許可してください。

Cron は 5 分ごとなので、通知は指定時刻から最大 5 分ほど遅れて届きます。
端末の電源が長く落ちていた場合、1 時間以上前の通知は送らずに畳みます（起動時にまとめて鳴るのを避けるため）。

### 検証できていること・いないこと

- 本文の暗号化（RFC 8188/8291）は、RFC 著者による参照実装 `http_ece` で復号できることを確認済み
- VAPID の JWT は ES256 として公開鍵で検証できることを確認済み
- API と定期実行はローカルの Worker + D1 で通しで確認済み（登録・置き換え・解除・古い通知の畳み込み）
- **実際の push サービス（FCM / APNs）への配信だけは未検証**です。デプロイ後、実機で 1 件試してください

## 見た目について

クラブのフライヤーの文法を借りています。2 色刷り（**マゼンタ**が主役、**シアン**は
「ファイナル」専用の第 2 インク）、圧縮した太い見出し、細い罫線。琥珀と赤は締切の状態にだけ使い、
色が意味を持つようにしています。

**ダークとライトの 2 種類**があります。ライトは黒地の単純な反転ではなく、
「白い紙に同じ 2 色を刷った状態」として組み直しています。地はマゼンタ側へわずかに寄せた
ニュートラルグレー、インクが紙に沈まないようマゼンタとシアンは暗めの版を使います。設定タブで `端末に合わせる / ダーク / ライト` を選べて、
選んだ内容は次回も残ります。夜の会場ならダーク、昼の稽古場や屋外ならライトが見やすいはずです。

見出しと数字は **Anton**。欧文のみ・約 19KB なのでビルド時に data URI として埋め込んでいて、
外部へのフォントリクエストは発生しません（会場で電波が悪くても見出しが崩れない）。
和文は端末標準のゴシックに任せています。

準備状況は割合のバーではなく **4 本の目盛り**（入金・音源・会場・ジャッジ）で、
「何が残っているか」がそのまま見えるようにしました。

タブバーのアイコンは出来合いのセットではなく、この画面の線の太さと角の作りに合わせて
`src/components/icons.tsx` に引いています。設定は歯車ではなくミキサーのフェーダーにして、
音を扱う道具立てで揃えました。選択中は線を少し太らせています。

## 使い方

```bash
npm install
npm run dev      # 開発サーバー（http://localhost:5173）
npm run test     # ロジックのテスト（161 件・worker のぶんを含む）
```

## 構成

ロジックは `src/lib` に純粋な TypeScript として切り出してあり、UI なしでテストできます。

```
src/
├── types.ts                     コンテスト・入金・音源・ジャッジ・ファイナルなどの型
├── lib/
│   ├── date.ts                  日付キー（YYYY-MM-DD）の計算とカレンダーの升目
│   ├── contest.ts               準備状況の判定、並び順、絞り込み、ファイナルを含む「次に来る日」
│   ├── schedule.ts              開催・ファイナル・締切を 1 件ずつに開いた予定と、その検索
│   ├── reminder.ts              通知予定の組み立て（開催日・ファイナル・入金期限・音源期限）
│   ├── ics.ts                   iCalendar の書き出し（VALARM つき）
│   ├── map.ts                   Google マップのリンク生成
│   ├── factory.ts               新規データの初期値と保存データの補正
│   ├── theme.ts                 配色（ダーク / ライト / 端末に合わせる）の決定
│   ├── pushSchedule.ts          サーバーへ預ける通知予定の組み立て
│   ├── backup.ts                控えの書き出し・読み込み・取り込み方
│   └── *.test.ts                上記のテスト
├── content/privacy.json         プライバシーポリシーの文面（公開ページと共通）
├── data/sampleContests.ts       デモ用データ（起動時刻を基準にした相対日付）
├── hooks/
│   ├── useLocalStorage.ts       localStorage への保存
│   ├── useNotifications.ts      開いている間の通知
│   ├── usePush.ts               購読と予定の同期（閉じていても届く通知）
│   └── useTheme.ts              配色の保存と <html data-theme> への反映
├── components/
│   ├── HomeView / CalendarView / ReminderView / SettingsView   4 つのタブ
│   ├── ContestDetail / ContestForm / ContestCard               コンテストの詳細・編集・一覧
│   ├── FilterBar                                               ジャッジ・ファイナル権での絞り込み
│   ├── FinalPanel / JudgePanel / ReviewPanel                   詳細内の各セクション
│   ├── Welcome / PrivacyView                                   初回の案内・プライバシーポリシー
│   ├── BottomNav / icons.tsx / ui.tsx                          タブバー・アイコン・共通パーツ
├── assets/anton-latin.woff2     見出し用フォント（ビルド時に data URI へ埋め込み）
└── App.tsx                      画面の組み立て

public/sw.js                     Service Worker（プッシュの受信と通知の表示）

worker/                          通知サーバー（Cloudflare Workers）
├── src/push.ts                  Web Push の暗号化と VAPID（WebCrypto のみ）
├── src/api.ts                   受け取り内容の検証と配信対象の選別
├── src/index.ts                 HTTP と 5 分ごとの定期実行
├── schema.sql                   D1 の表
└── wrangler.toml                デプロイ設定
```

日付は `new Date('2026-08-20')` が UTC 解釈になる罠を避けるため、必ず年月日を分解してローカルの
`Date` を作っています（`src/lib/date.ts`）。

## 配布に向けて用意してあるもの

- **プライバシーポリシー** — 文面は `src/content/privacy.json` の 1 か所。設定タブから読めるほか、
  `node scripts/build-privacy.mjs` で `public/privacy.html` を書き出します。
  ストアの審査では公開 URL を求められるので、配信したサイトの `/privacy.html` を出せます
- **問い合わせ先** — `.env` に `VITE_SUPPORT_EMAIL` を入れると、設定タブに導線が出ます（未設定なら項目ごと隠れます）
- **バージョン表示** — `package.json` の version を設定タブに出します。不具合の連絡でどの版か分かるように
- **使い方マニュアル** — `docs/manual.md`。ホーム画面への追加から通知・バックアップまで、初めて触る人向けに順番どおり

## これから実装するとしたら

- 端末をまたいだ同期（いまは控えのファイルを渡す形。自動で揃えるにはアカウントとサーバーが要ります）
- 画面のキャッシュ（いまの Service Worker は通知の受信だけで、オフライン表示はしない）
- 音源ファイルそのものの保管、提出フォームの URL 管理
- チーム機能（メンバーごとの入金状況の管理）
