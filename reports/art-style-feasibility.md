# 受領した原画候補の適合性評価

対象: 2026-09-02 にユーザーから受領した1536×1024のシート（案B「刺繍とフェルトの手芸カワウソ ステッチ」10ポーズ）

すべての数値は `scripts/build_apng.py` の `write_with_roundtrip()` を用いた実測であり、推定ではない。

## 1. 画像の実測値

| 項目 | 実測 | 発注書の要求 | 判定 |
|---|---|---|---|
| 形式 | PNG / mode=RGB | RGBA（透過必須） | **FAIL** |
| 透過画素 | 0 | 背景は透過またはクロマキー | **FAIL** |
| 背景 | クリーム `#F7F4E5` の紙テクスチャ（背景色±6以内は42.6%） | 均一 | **FAIL** |
| 寸法 | 1536×1024（10体を1枚に配置） | 1マス720×720 | **FAIL** |
| ユニーク色数 | 318,284（全体） / 14,911（1体を180px化した不透明部） | 少数の共通色 | **FAIL** |
| 焼き込み文字 | タイトル・ラベル・説明文あり | 文字・ラベル・透かしを入れない | **FAIL** |
| ラベル番号 | `1,2,1,4,1,6,7,8,9,10`（`1`が3回、`3`と`5`が欠番） | — | 生成の制御精度の問題 |

## 2. 容量の実測（§9-9 ハード上限 300,000 bytes / 目標 285,000 bytes）

1体目を180×180へ収め、20フレーム・4000msのAPNGとして書き出した実測値。

| 条件 | 実測 | 判定 |
|---|---:|---|
| 動きゼロ（20枚とも同一画像） | 1,180,782 bytes | **FAIL**（上限の3.9倍） |
| 胴体を画素単位で固定し、56×56の小領域のみ可動 | 234,358 bytes | PASS |
| 全身が毎フレーム移動（お辞儀・ジャンプ・のけぞり相当） | 1,179,874 bytes | **FAIL**（上限の3.9倍） |

### 平坦化するとどこまで下がるか（全身移動の条件）

| 処理 | 色数 | 実測 | 判定 |
|---|---:|---:|---|
| 原画のまま | 14,911 | 1,179,874 | FAIL |
| 粒子除去 median r=2 | 14,826 | 945,172 | FAIL |
| 粒子除去 median r=3 | 10,648 | 686,463 | FAIL |
| 粒子除去 median r=5 | 5,767 | 473,666 | FAIL |
| 粒子除去 r=3 + 12色 | 12 | 249,545 | PASS |
| 粒子除去 r=5 + 12色 | 12 | 181,140 | PASS |
| 粒子除去 r=5 + 10色 | 10 | 154,017 | PASS |
| 粒子除去 r=7 + 10色 | 10 | 129,727 | PASS |

**16色へ量子化しただけでは 398,332 bytes で不合格。粒子（紙の目とフェルトの繊維）を除かない限り
色数を減らしても上限に入らない。** 容量を支配しているのは色数ではなく画素単位のざらつきである。

## 3. 重要な限界

上表の「粒子除去＋量子化」は**後処理での機械的な平坦化**であり、実際にやってみると
ステッチの輪郭とボタンの目が消失し、デザインが成立しなくなる（`flatcompare` で確認済み）。

したがって **後処理で救うことはできない。フラットな描画として最初から生成し直す必要がある。**

## 4. 副次的な発見（検査系の妥当性）

同一フレームを20枚並べた場合、Pillow は `OP_NONE/OVER` と `OP_NONE/SOURCE` で
**フレームを1枚へ畳んで**しまい 59,971 bytes の出力を返した。
`build_apng.py` のラウンドトリップ検証がこれを `frame count 1 != 20` として棄却しており、
`num_frames=20` を満たさないAPNGが静かに採用される事故を防いでいることを実地で確認した。

## 5. 32px 視認性

180pxおよび32pxで目視した結果、32px ではステッチの輪郭が斑点状に潰れ、
判別できる要素はボタンの目のみだった。§6-C の「32px表示で目・口・主役要素・シルエットのうち
最低2つを即座に認識できる」に対し、現状は**目1つのみ**で不足している。

## 6. 決定（2026-09-02）

ユーザーの選択により、以下を確定した。

| 項目 | 決定 |
|---|---|
| 基準デザイン | **案B「刺繍とフェルトの手芸カワウソ ステッチ」へ変更**（案C「レトロソフビ ダイオウ」は不採用） |
| 描画方針 | **フラット描画で再生成**。10色ベタ塗り、粒子・繊維・布目・にじみを一切描かない |
| 受領シートの扱い | 方向性の確認用として採用。**原画としては不採用**（透過なし・文字焼き込み・粒状テクスチャ・1枚に10体・寸法不一致） |

これに伴い `style-lock.json` と `design-brief.md` を全面差し替え、
`emoji-plan.json` の案C固有記述（提灯・尾ひれ・ソフビ成型・抜き穴）53箇所＋語彙66箇所を
ステッチ機構へ置換した。全ゲートを再実行して FAIL=0 REVIEW=0 を確認済み。

### 併せて是正した設計上の欠陥

移動量と安全域が両立していなかった。案Cの本体寸法（96×118）では
使用可能域164pxに対する移動量の上限が `164 - 118 = 46px` となり、
016 やったー（54px）と 038 キラキラ（60px）が**物理的に安全域へ収まらなかった**。

本体を 96×108 へ縮小して上限を56pxとし、この十分条件
`d <= 164 - max(w, h)` を `scripts/check_plan_gates.py` の機械検査として恒久化した。
意図的に超過させると FAIL を返すことを確認済み（現在の違反は0件）。
